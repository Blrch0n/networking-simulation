# Багшид үзүүлэх 10 минутын дараалал

Live: https://networking-simulation-beta.vercel.app/. Локал: `make demo` → http://127.0.0.1:8000. Анх удаа `make setup`.

Дээд цэс: «Газрын зураг», «Алгоритм», «Харьцуулалт». Нэг удаад сонгосон хэсэг л харагдана.

1. **0:00–1:00 — Асуудал.** 21 аймгийн төв + нийслэл = 22 орой. Кабель = чиглэлгүй, уртаар жинлэсэн ирмэг. MST, богино зам, нэг тасралтын хамгаалалтыг харьцуулна.
2. **1:00–2:30 — MST.** Улаан MST: 21 кабель, 3952.29 км, 21 гүүр. Хоёр хот сонгоод «Сонгосон замд тасралт турших». Сүлжээ салж, бүх сүлжээний RTT “—” болно. Эхлэх хотоос хүрэхгүй хотуудыг харуул. «Сэргээх».
3. **2:30–4:00 — 2-Edge.** Цэнхэр 2-Edge: 29 кабель, 6338.17 км, 0 гүүр. Замын кабелийг тасалж өмнөх/дараах маршрут, нэмэгдсэн км ба RTT-г харьцуул. «Сэргээх».
4. **4:00–6:00 — Алгоритм.** «Алгоритм» → Dijkstra → «Алхамчилж үзэх». Хамгийн бага боломжит зайтай хотыг баталгаажуулж хөршийн зайг шинэчилнэ. «Үр дүн». Дараа Kruskal сонгож кабелийг уртын дарааллаар нэмэх, цикл үүсвэл алгасахыг үзүүл. Overlay үндсэн графыг өөрчлөхгүй. Газрын зураг цэс рүү буцахад хэвийн зураг буцна. Tarjan сонговол гүүрүүд шар, Greedy сонговол нэмэлт кабелийн хүснэгт харагдана.
5. **6:00–7:00 — Нэг кабелийн бүх шалгалт.** «Харьцуулалт» → «Шалгалт эхлүүлэх». 2-Edge 29/29 холбоотой; worst бүх хосын max RTT 24.64 ms (Алтай—Баянхонгор). Туршилт бүр эрүүл сүлжээнээс эхэлнэ. MST 0/21, Full Mesh 231/231.
6. **7:00–8:00 — Өртөг.** «Харьцуулалт» цэс дэх хүснэгт болон зардлыг харуул. 2-Edge нь MST-ээс 60.37% урт нэмсэн. USD/км нь жишээ таамаглал. Full Mesh: 231 кабель, 152750.58 км.
7. **8:00–9:00 — Олон тасралт.** Газрын зураг → «Тасралтын тохиргоо» → «Олон кабель зэрэг таслах». Хоёр кабель туршиж тус бүрийг эсвэл бүгдийг сэргээ. 2-Edge нь олон тасралтад баталгаа өгөхгүй. Эцэст бүх тасралтыг сэргээж олон тасралтыг унтраа.
8. **9:00–10:00 — Хүрээ ба асуулт.** Kruskal, Tarjan, Dijkstra-г хэрэглэсэн. 2-Edge augmentation нь heuristic, глобал optimum батлаагүй. Урт нь географийн ойролцоо; бодит трасс биш. RTT = км × 0.01, төхөөрөмжийн саатал ороогүй. Нэг логик кабелийн хамгаалалт нь хотын гэмтэл, физик коридорын бие даасан байдлыг нотлохгүй.

Өгөгдөл, топологи эсвэл failure mode өөрчлөхөд тасралт цэвэрлэгдэнэ. Цэс солиход идэвхтэй олон тасралт хэвээр: тоо, тасарсан кабелиуд, сэргээх товч үндсэн дэлгэцэд харагдана.

Бодит FRR/OSPF лаборатори зөвхөн локал. Шалгалт үнэхээр passed үед үзүүлнэ; Docker боломжгүй бол skipped гэж тайлбарлана. Графын замыг бодит ping/OSPF convergence гэж танилцуулахгүй.

Пакет үзүүлэх: хоёр хот сонгоод «Пакет илгээх». Хөх пакет хүрэх хотод очоод ногоон хариу болж эхлэх хотдоо буцна. «Очих», «Буцах», «Очоод буцлаа» төлөвүүд харагдана. Удаашруулсан үзүүлэн тул дэлгэцийн секундийг RTT гэж тайлбарлахгүй; тоон RTT нь км × 0.01 хэвээр. Зам/тасралт өөрчлөхөд хөдөлгөөн зогсоно, дараагийн илгээхэд шинэ зам ашиглана.

«Traceroute»: hop 1 нь эхлэх хотын дараах router. Эхний hop private 10.0.x.x, цааших backbone interface нь public үүрэгтэй сургалтын 203.0.113.x хаягтай. Эхлэх хот hop-д тоологдохгүй. Мөр бүрийн 3 probe ижил тооцоолсон RTT-тэй (хуримтлагдсан км × 0.01); бодит latency, timeout эсвэл load balancing зохиохгүй. Тасралтын дараа шинэ замаар жагсаалт шинэчлэгдэнэ. Trace нь эхлэх → хүрэх чиглэлийнх хэвээр, animation-ийн одоогийн хот тодорно.

## Starlink жишээ

2-Edge сонгоод хоёр өөр кабелийг тасална. Тасралтууд автоматаар хуримтлагдана. Хоёр дахь тасралтын дараа кабелийн зам үлдсэн байсан ч пакет Source → Starlink → Destination замаар явна. «Пакет илгээх» товчоор очих, буцах хөдөлгөөнийг харна. Нэг кабелийг сэргээж тасралт нэг болговол кабель руу буцна.

Хоёр хотод терминал байна гэж үзсэн сургалтын загвар. 60 ms нь таамаг; «Тасралтын тохиргоо»-д өөрчилж болно. Хиймэл дагуулын байрлал жишээ бөгөөд бодит тойрог зам, ISP холболт биш. Кабелийн холболтын үзүүлэлт тусдаа хэвээр.

Source/Destination IP замын турш хэвээр; хариу пакет дээр хоёр тал солигдоно. «Одоогийн → Дараагийн hop» нь хөдөлгөөнтэй хамт солигдоно.
