# Багшид үзүүлэх 10 минутын дараалал

Live: https://networking-simulation-beta.vercel.app/. Локал: `make demo` → http://127.0.0.1:8000. Анх удаа `make setup` ажиллуулна.

Бэлтгэл: «Өгөгдөл засах → Анхны 22 хотыг сэргээх». Эхлэх Улаанбаатар, хүрэх Ховд сонгохдоо «Зам олох» view рүү орно. Явцын тасралт refresh хийхэд цэвэрлэгдэнэ.

1. **0:00–1:00 — Асуудал.** «Сүлжээ байгуулах». Монголын 21 аймгийн төв ба нийслэл = 22 орой, кабель = чиглэлгүй уртаар жинлэсэн ирмэг. Зорилго нь бага кабелиар холбох, зам олох, тасралтад тэсвэрийг шалгах.
2. **1:00–2:30 — Kruskal.** MST сонго. «Алхамчилж үзэх», «Дараах алхам». Богино кабель хоёр өөр бүрэлдэхүүнийг холбовол нэмнэ; цикл үүсгэвэл алгасана. Slider-аар хэсэгчилж үзэж болно. «Үр дүн»: 21 кабель, 3952.29 км, 21 гүүр. Энэ overlay нь бодит суурь сүлжээг засахгүй. «Тайлбар хаах».
3. **2:30–3:30 — Нөөц дизайн.** 2-Edge: 29 кабель, 6338.17 км, 0 гүүр. Алтай—Баянхонгор кабель дарж ямар учраас нэмэгдсэн, хэдэн гүүр арилгасныг харуул. Урт/арилгах-гүүрийн тооны heuristic; глобал optimum гэж хэлэхгүй. «Гурван загварыг харьцуулах» ба «Зардлын харьцуулалт»: MST-ээс 60.37% урт нэмсэн; нэг км-ийн үнэ нь жишээ таамаглал.
4. **3:30–5:00 — Dijkstra.** «Зам олох», эхлэх ба хүрэх хот сонго. «Алхамчилж үзэх». Хамгийн бага боломжит зайтай хотыг баталгаажуулж хөршийн зайнуудыг шинэчилнэ. «Хотуудын зайг харах» хүснэгтэд ∞ нь олдоогүй зай; бусад баталгаажаагүй утга tentative. «Үр дүн» нь тооцоолсон хамгийн богино зам. «Тайлбар хаах».
5. **5:00–6:30 — Туршилт.** «Энэ замд тасралт турших →», дараа «Сонгосон замд тасралт турших». Тасарсан кабель хар тасархай; өмнөх зам нил ягаан цэгэн; одоогийн зам улбар шар. Доорх хоёр төлөвөөс урт ба RTT-ийн зөрүүг тайлбарла. «Сэргээх». MST рүү сольж cut хийхэд сүлжээ салж, бүх сүлжээний RTT “—” болохыг харуул; хүрэхгүй хотууд нь сонгосон эхлэх хотоос хамаарна.
6. **6:30–7:30 — Бүх нэг тасралт.** 2-Edge → «Шалгалт эхлүүлэх»: 29/29 холбоотой, worst max RTT 24.64 ms (Алтай—Баянхонгор). Туршилт бүр эрүүл сүлжээнээс эхэлнэ. Энэ нь одоогийн олон cut дээр нэмж таслах биш. MST 0/21, Full Mesh 231/231. 50 ms нөхцөл бүх хосын max RTT-д хамаарна.
7. **7:30–8:30 — Олон тасралт.** «Олон кабель зэрэг таслах»-ыг сонгоод хоёр кабель тасал. Тус бүрийг эсвэл бүгдийг сэргээ. 2-Edge нь дурын нэг кабелийн тасралтад баталгаатай; хоёр ба түүнээс олон тасралтад баталгаа өгөхгүй. View солиход тасралт хадгалагддаг; горим/топологи/граф өөрчлөхөд цэвэрлэгдэнэ.
8. **8:30–9:30 — Өөрийн загвар.** «Өгөгдөл засах»-д `demo-city`, «Туршилтын хот», 48.1, 106.1, автомат кабель сонгоод хадгал: 23 хот, 253 хос. Undo болон анхны өгөгдөл сэргээхийг үзүүл. Координат өөрчлөхөд кабелийн урт хадгалагдана.
9. **9:30–10:00 — Хүрээ.** Кабелийн урт бол газарзүйн ойролцоо, бодит трасс баталгаажаагүй. RTT = км × 0.01; router processing/queueing ороогүй. Нэг логик кабелийн хамгаалалт нь хотын гэмтэл, нэг trench доторх хоёр кабелийн физик хамгаалалтыг нотлохгүй. Шинэ алгоритм зохиогоогүй; Kruskal, Tarjan, Dijkstra-г өөрийн интерактив planning workspace-д хэрэглэсэн.

Бодит FRR/OSPF лаборатори зөвхөн локал. Docker шалгалт үнэхээр passed үед тусдаа үзүүлнэ; unavailable бол skipped гэж тайлбарлана. Графын замыг бодит ping эсвэл OSPF convergence гэж танилцуулахгүй.

Хэмжилт: `docs/planning-results.json`, `docs/planning-performance.json`. Хуучин screenshot/тайлангийн тоог одоогийн үр дүнтэй хольж хэрэглэхгүй.
